# LocalRelay architecture and frozen boundaries

React 19 + TypeScript + Vite static frontend. React Router implements the specification route contract; unknown UI routes show not-found. Zod validates profile/card/model/event/stored/study contracts. IndexedDB (idb) separates requests, preferences/phone overrides and opt-in evaluation records. Vercel only serves same-origin assets. No server inference, translator, database or SMS gateway.

An inference worker loads hash-verified float32 weights once per page session and performs shared hashed-feature linear inference. The service worker is a separate Workbox cache proxy, not a background agent. Shell, route JS/CSS, worker, model, profiles, manifest and icons are precached. A generated asset readiness manifest checks actual cached bytes/hash; the manifest itself is cached after first preparation. Missing/incompatible assets never mean “ready”. First download needs internet. Browser eviction remains possible.

Phases implemented in dependency order: contracts, manual workflow, trained model, offline preparation, SMS/evaluation integrations, packaging. See phase-gates.md for initial gates; final evidence remains separate.

Review state is local component state until queue: missing/ambiguous fields demand explicit choices; unsupported requirements block. The persisted request starts READY_TO_SEND only after a successful write. Visitors explicitly accept every required field; no default children/meal count. Manual and AI entry share schedule/profile validation, review, renderer and downstream path. Exact supported grammar is intentionally small; learnable routing is experimental and may abstain excessively.

Records freeze selected profile/phone, card, exact rendered body, model/template versions and resolved dates. New revisions revalidate and atomically supersede the old record; same correlation prefix + incremented revision. Opening a composer, reported sending and manually entered replies have distinct events. Offers freeze; identical duplicates are idempotent; conflicting later terms stop progression. Exact acceptance must be communicated back; matching acknowledgement records agreement. Manual entry is not authenticated SMS.

Storage version 1 is the first schema; no older public schema exists. Upgrade callback creates separate stores; schema-invalid records produce a visible error and are not silently reinterpreted or deleted. A future schema requires an explicit migration before opening version 2. Failures/quota errors do not queue a record. Storage denial, blocked upgrade and invalid records are visible; deleting requests/all local data never calls a cancellation transport. Retention cleanup runs on local reads (including app startup), not a guaranteed background timer.

Updates are prompted and activation is available from Home, after visitors leave unsaved review. Existing records retain exact original SMS; no reparse of “tomorrow”. CSP allows only local scripts/workers/styles/assets/connects. Inputs are rendered through React escaping, never raw HTML. Hosting still sees ordinary asset metadata; IndexedDB is not app-encrypted and SMS is not end-to-end encrypted.

Demo profiles have null phones. A private locally entered phone snapshot enables development composer testing only. One meal-included or one no-meal service per profile; BDT and Asia/Dhaka fixed; adult minimum 1; zero children/meals chosen explicitly; no general food customization, transport/accessibility/payment fields. Bangla display uses the platform font; actual phone font/rendering must be tested.
